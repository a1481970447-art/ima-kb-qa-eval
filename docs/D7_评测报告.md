# ima 知识库问答质量评测报告

> AI-PM Demo · 评测工作台 ｜ 数据截至 2026-08-31 ｜ 50 条金标 · 双层评分 · 三层归因
> 一句话结论：**端到端正确率 82%；9 条错误经人工仲裁后，检索层 44% / 生成层 44% / 数据层 11%——数据层错误需要"过期文档高位排序 + 生成层采信"联合失败才爆发，本评测体系能把这个机制完整暴露出来。**

---

## 0. 声明（先说清楚边界）

1. **复现架构，非定量指控**：ima 的 MCP 接口不提供问答 API，端到端评测无法在 ima 侧自动化（D1 实测结论）。本报告基于一套**贴近 ima 可观察行为的手写 RAG 复现 pipeline**（切块策略、引用行为对齐 D1 观察记录），结论用于**评测方法论演示**，不构成对 ima 真实质量的定量指控。
2. **裁判与被测同模型**：生成与 LLM-as-judge 均使用混元 hy3（保持"腾讯叙事"一致性）。自我增强偏差通过"每指标 3 次取多数 + 人工仲裁"缓解但未消除；金标 100% 可溯源到文档原文，10% 以上样本经人工复核。
3. **时效**：评测数据截至 2026-08-31，涉及"最新版本"类问题（F-07/F-05）以当日语料为准。

---

## 1. 评测背景与现状分析

### 1.1 为什么评测 ima 的知识库问答

ima（腾讯智能工作台）的核心场景是"个人/团队知识库问答"：用户导入文档，以自然语言提问。这类产品有一个结构性问题——**问答质量对用户是黑盒**：

- 用户不知道答案基于哪篇文档、这篇可信吗、库里有没有冲突；
- 答错时没有反馈出口，错误被默默接受或默默流失；
- 库越用越厚，旧内容不会自动退休。

### 1.2 重度使用发现（D1，20 篇真实语料 · 24 条 badcase）

把自己的 20 篇真实学习资料（ima 产品资料、混元定价、RAG 论文）导入 ima，完整走了一遍"导入 → 等待 → 提问 → 核对 → 反馈"旅程，记录 24 条 badcase + 5 个体验崩点。四个高频错误场景：

| 场景 | 实测样例 | 体感频率 |
|---|---|---|
| 错源高排 | 问"ima 什么时候上线"，含事实错误的用户帖排第一（"今年 2 月上线"），权威百科排第五 | 高 |
| 过期信息无标记 | 问"支持哪些平台"，高排的是一年前"仅三种使用方式"的旧帖 | 高 |
| 库外问题不拒答 | 问内部参数/竞品数据，检索照样返回一堆"长得像"的文档 | 中 |
| 细节埋深 | 长文档第 5 节的条款问答不上来，高亮的是节标题而非答案段落 | 中 |

另有两个流程性崩点：解析静默降级（入库后约 4 分钟内提问，答案不含未解析文档且**零提示**，差点造成假 badcase）；反馈闭环缺失（能明确指出错误源，却没有任何入口反馈）。

**结论：这不是模型问题，是知识库质量"不可见、不可控、无反馈闭环"的产品问题。** 这正是本次评测要量化的对象。

## 3. 指标体系与评分器（D3/D4）

### 3.1 双层指标（规则自动 + LLM 裁判）

| 层 | 指标 | 测量方式 | 考核条数 |
|---|---|---|---|
| 检索层 | 检索命中率（top-k / top-3 双口径，附金标排名） | 规则，自动 | 40 |
| 检索层 | 引用忠实度（faithfulness，RAGAS 口径） | LLM-as-judge | 2 |
| 生成层 | 事实正确性（factuality） | LLM-as-judge | 34 |
| 生成层 | 完整性（completeness） | LLM-as-judge | 17 |
| 边界能力 | 拒答准确率（应拒答不乱答 + 不应拒答不误拒，双向） | 规则，自动 | 10 |
| 体验层 | 端到端延迟 | 规则，自动 | 50 |

### 3.2 裁判的反偏差设计

- **每指标跑 3 次取多数**（temperature 0.7 > 生成侧 0.2，测裁判稳定性而非确定性复读），agreement < 3/3 自动进人工仲裁队列；
- system prompt 显式对抗：冗长偏差（"长短不影响打分"）、知识泄漏（"只依据评测材料，不用你自己的产品知识"）、输出约束（单行 JSON + 正则容错提取）；
- 每条题按 eval_set 的 metrics 字段裁剪考核维度，不无差别全跑（成本与噪声双控）。

### 3.3 复现 pipeline（贴近 ima 可观察行为的三个决策）

手写最简链路（零框架依赖，仅 openai SDK + numpy + pypdf）：解析 → 切块（标题切节 + 滑窗 600/120 + 章节标题前缀 + 每篇摘要 chunk）→ 混元 embedding（997 chunks，增量缓存）→ cosine top-k（可配置）→ hy3 生成（内置拒答规则，给拒答题公平机会）。20 篇语料与 D1 导入 ima 的完全相同，**同一批文档、同一批问题，ima 答一遍、复现架构答一遍，错误形态可对照**。

## 4. 总体结果

### 4.1 总分

| 指标 | 结果 | 备注 |
|---|---|---|
| **端到端正确率** | **82%**（错误率 18% = 9/50） | fatal 口径：关键事实错 / 无依据 / 要点缺失 / 错误拒答 |
| 检索命中率（top-3，文档级） | 87.5%（35/40） | 已知会高估检索质量（见 6.2 F-07 教训） |
| 拒答准确率 | **100%**（10/10） | 库外问题全部正确拒答，含 J-07 陷阱题 |
| 事实正确率 | 67.6% correct / 14.7% partial / 17.6% incorrect | 裁判 majority，34 条考核 |
| 完整性 | 41.2% complete / 35.3% partial / 23.5% missing | **最大短板**：要点覆盖不足是普遍问题 |
| 引用忠实度 | 2/2 supported | 考核样本量小（弱证据），主要作为归因信号使用 |
| 端到端延迟 | 均值 14.9s / p50 14.5s / p90 25.7s / max 32.5s | 检索 <4s，主要耗时在生成侧（hy3 思考） |

弱问题（非 fatal 但存在 partial 判定）另有 8 条：F-05、F-12、M-02、R-02、R-06、R-07、R-09、R-12——**partial 不计入错误，避免把"不够精确"夸大成"错误"，保证归因结论的保守性**。

### 4.2 分题型错误率

| 题型 | 错误率 | 解读 |
|---|---|---|
| fact（20） | 15%（3/20） | 长文档细节埋深是主因 |
| reasoning（15） | 20%（3/15） | 跨语言归纳、观点综合偏弱 |
| refusal（10） | **0%** | 边界能力守得住 |
| **multi_doc（5）** | **60%（3/5）** | **最弱环节**，与 D1 痛点预判一致 |

### 4.3 跑批执行

50/50 全量完成，耗时 23.9 分钟，0 失败；裁判并发 4 workers；每题完成即写 checkpoint（断点续跑机制全程未启用——一次跑通）。API 成本 < 10 元（方案预算 50 元内）。

## 5. badcase 三层归因（本 demo 的差异化核心）

### 5.1 归因决策树（自动）

```
错误样本
├── 拒答题应拒答未拒答 ─────────────→ 【生成层】拒答边界执行失败
├── 非拒答题
│   ├── 错误拒答：金标在 top-3 → 生成层 ／ 金标未进 top-3 → 检索层
│   ├── 金标未进 top-3：rank 4-8 弱命中 → 检索层（排序）；未召回 → 检索层（切块/召回）
│   ├── multi_doc 金标未全部进 top-3 → 检索层（部分召回）
│   └── 金标在 top-3 但答错：数据层信号命中 → 数据层；否则 → 生成层
```

数据层自动判据（两条，命中其一即归数据层）：① 忠实度-正确性交叉（faithfulness=supported 且 factuality=incorrect——回答忠实于上下文但与金标矛盾 ⇒ 上下文本身是错的）；② 陷阱文档高位召回且被采信（对应 trap_note 预埋）。

### 5.2 各层错误占比（人工仲裁后终版）

| 归因层 | 条数 | 占错误 | 占全体 | 对应产品动作 |
|---|---|---|---|---|
| 检索层 | 4 | 44% | 8% | 引导用户调整文档结构 / 章节级检索优化 |
| 生成层 | 4 | 44% | 8% | badcase 反馈闭环 / prompt 迭代 |
| **数据层** | **1** | **11%** | **2%** | **知识库健康度：冲突检测、过期提醒、信源权威度标注** |
| 合计 | 9 | 100% | 18% | 归因覆盖 9/9，无 unknown |

**为什么这个三分法是 PM 视角**：检索层和生成层错误有技术解法（调切块、调 prompt、换模型），数据层错误**无法靠调模型解决**——只能靠产品机制让用户治理知识库。把错误归因到"库本身脏"，是只有 PM 会得出的结论。

### 5.3 九条错误样本全表（自动归因 → 人工仲裁终判）

| ID | 题型/子类 | 错误现象 | 自动归因 | 终判 | 要点 |
|---|---|---|---|---|---|
| F-07 | fact/outdated_info | 错误拒答 | generation | **retrieval** ✏️ | 文档级命中掩盖章节级未召回，改判 |
| F-16 | fact/deep_detail | 错误拒答 | retrieval | retrieval | 长文档细节埋深，金标 chunk 未召回 |
| F-17 | fact/timeline_detail | 错误拒答 | retrieval | retrieval | 时间线 chunk 未召回 |
| M-01 | multi_doc/cross_doc | 错误拒答 | generation | generation | 信息在上下文，未建立"文档↔词条"映射 |
| M-03 | multi_doc/two_reports | 要点遗漏 | retrieval | retrieval | rank=6 弱命中，部分召回 |
| M-04 | multi_doc/outdated | 采信过期清单 | retrieval | **data** ✏️ | 过期表述 TOP1 被采信，复合错误主因判数据层 |
| R-01 | reasoning/cross_lang | 列举不完整 | generation | generation | 跨语言检索成功，归纳不足 |
| R-04 | reasoning/cross_lang | 提取不全即拒答 | generation | generation | FP4 Not Extracted 的原样复现 |
| R-13 | reasoning/viewpoint | 观点归纳偏离 | generation | generation | 有据但偏离金标核心 |

✏️ 人工改判 2/9（自动树误判率 22%）。9 条错误中 5 条可回溯到 D1 在 ima 的实测 badcase（A-05/A-09/A-13/A-18/A-22），4 条为定向新增压力题。

### 5.4 人工复核与裁判分歧仲裁

- 复核范围：9 条错误全量 + 复核清单 11 条（裁判分歧 4 条 + partial 弱问题 + 数据层判定 + 边界 case）；
- 裁判分歧率约 4%（5/约 130 指标实例），**majority 全部被采信、无一翻转**——"3 次取多数"机制有效性得到直接验证；
- 两条改判依据：
  - **F-07（generation→retrieval）**：D02 命中的是无关章节，金标"模型切换菜单"章节并未召回，模型"无据可答而拒答"是诚实行为。**方法论教训：文档级命中率会高估检索质量，需章节级口径**（已写入 D6 看板）。
  - **M-04（retrieval→data）**：D10 过期表述 TOP1 高位命中且被采信为权威答案（数据层埋点在复现架构中真实触发）；权威清单未召回是次因、模型无信源权威度取舍能力是第三因。复合错误按主因判数据层。

### 5.5 四个关键洞察（比数字更值钱的部分）

1. **数据层错误在复现架构中被低估**：仅 1/9（11%），远低于 D1 在 ima 实测的体感。原因：数据层错误的爆发需要"过期文档高位排序 + 生成层采信"联合失败，复现 pipeline 恰好两点都与 ima 不同（向量分布、指令遵从）。M-04 证明机制可触发、频率被复现架构低估——**这正是必须声明"方法论演示而非定量指控"的原因，也是"评测体系要长在真实产品上"的论据**。
2. **错误拒答是最大错误形态（4/9）**：拒答话术未区分"库内确实没有"与"召回不足"。产品启示：反馈闭环应让用户区分这两种"没答案"——前者引导补文档，后者是检索 bug，走向完全不同。
3. **R-04 是 FP4 Not Extracted 的自我复现**：用 Seven Failure Points 论文定义的失败点框架，诊断出了对该论文提问的同类失败（上下文已含七点，模型仅提取 FP1 即拒答）——评测体系的自洽性彩蛋。
4. **M-01 揭示元数据隔离与信源身份的矛盾**：front-matter 剥离防住了元数据污染（D1 教训 A-14），却也剥掉了"腾讯云百科/搜狗百科"的词条出处，模型无法回答"两个词条的差异"。**知识库健康度设计必须同时考虑污染防护与信源可追溯**——纯 PM 视角的权衡洞察。

## 6. 评测体系构建过程中踩的坑（方法论沉淀）

1. **裁判证据面 ≠ 被测证据面**（D4）：初版 faithfulness 裁判只喂 top-5 chunks，而生成用完整 top-k——R-15 合法引用 top-8 内容被误判"引用未提供的内容"。修复：忠实度判定基准与被测生成过程上下文完全一致。
2. **文档级命中率是粗口径**（D5/F-07）：文档命中 ≠ 章节命中。下一版看板与评测均应补章节级口径。
3. **解析状态是评测前置条件**（D1）：自动评测前必须轮询解析完成状态，否则得到假 badcase（实测第一轮 6 问全 miss 的教训）。
4. **自动归因树不能无人值守**：误判率 22%（2/9）恰恰证明"评测需要人机协同"——全自动归因负责规模化初判，人工仲裁负责终判与口径修正，两者的边界本身就是产品设计问题。

## 7. 改进建议（对应到 ima 的产品动作，含优先级）

| 优先级 | 建议 | 依据 | 预期效果 |
|---|---|---|---|
| **P0** | **知识库健康度面板**：冲突文档对检测 + 信源权威度/时效性标注 | D1 崩点 3（错源高排、冲突不可见）；M-04 数据层错误完整触发 | 数据层错误在源头被治理，而非靠模型兜底 |
| **P0** | **过期内容检测与降权**：版本/时间敏感字段识别，问答时提示"引用了 X 个月前的内容" | D1 现象 B；M-04 中 D10 旧清单 TOP1 被采信 | "库越用越厚、旧内容不退休"的结构性问题 |
| P1 | **badcase 反馈闭环**：答案级"有误"按钮 → 引导用户指认错误源/正确源 → 沉淀为评测集 | D1 崩点 5（反馈无出口）；错误拒答应区分两种"没答案" | 用户"发现答案错了"的瞬间转化为最高价值的标注数据 |
| P1 | **问答透明条**：回答标注"基于 N/M 篇已解析文档" | D1 崩点 2（解析静默降级） | 消灭最危险的"沉默降级"流失 |
| P1 | **拒答信号区分**：检索置信度低时前端展示"库内可能没有相关内容" | 错误拒答 4/9（最大错误形态） | 用户可区分"该补文档"与"检索 bug" |
| P1 | 生成侧：完整性专项（要点覆盖）与多文档关联能力 | 完整性仅 41.2% complete；multi_doc 错误率 60% | 直接改善两个最弱指标 |
| P2 | 检索范围圈定（文件夹/标签）、文件夹级批量导入 | D1 崩点 1/B-05 | 降低导入摩擦与负循环 |

**技术侧联动（给 ima 团队的 engineering note）**：章节级检索命中口径、多文档关联的检索策略（M-03 部分召回）、跨语言 chunk 检索（复现架构的 embedding 跨语言能力强于 D1 实测体感，值得交叉验证）。

## 8. 局限与下一步

| 局限 | 说明 |
|---|---|
| 复现 ≠ 真实实现 | 向量分布、排序权重、指令遵从均与 ima 不同；数据层错误频率被系统性低估 |
| 裁判与被测同模型 | hy3 自评的自我增强偏差仅被多数投票缓解 |
| 忠实度样本量小 | 仅 2 条专项考核 + 全量错误样本的归因交叉检验 |
| 50 条规模 | 够演示方法论，不够下产品级结论 |
