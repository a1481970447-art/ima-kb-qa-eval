## 二、Schema（D2 规划字段 + 溯源扩展）

```
id / type / subtype / question / gold_answer / gold_doc_id
+ gold_source_quote（原文摘录，可溯源的核心证据）
+ source_section（章节级出处）
+ difficulty / origin（badcase:A-xx | control:C-x | new）
+ trap_note（预期埋点：哪篇文档/哪层会诱导出错 → D5 归因对照表）
+ metrics（本题考核的 D4 指标：retrieval_hit / faithfulness / factuality / completeness / refusal_accuracy）
```

trap_note 是本集的关键扩展：**评测前就写好"预期会怎么错"**，D5 跑批后按此对照归因，避免事后编故事。

## 三、设计决策

1. **从 D1 长出来的，不是凭空造的**：19 条直接改造自 D1 实测 badcase，5 条对照组正向题证明"不是全军覆没"，新增 26 条按 D1 发现的四类弱场景定向补齐（细节埋深/过期数据/库外问题/跨语言）。
2. **数据层陷阱全覆盖**（对应 D1 第四节埋点清单）：
   - D08"今年2月上线"（F-01/J-03/M-01）｜D10 平台过期清单（F-05/M-04）
   - D11 vs D12 价格口径（M-02）+ 口径一致的对照组（M-05，防"逢题必称冲突"的过度泛化）
   - D05 旧版功能（F-18）｜D02 长文档细节埋深（F-02/F-03/F-04/F-20）｜D06/D07 同题多源（F-14/M-03）
3. **拒答题 10 条分三个亚型**：内部参数类（J-01/J-08）、竞品/未公开数据类（J-02/J-03/J-04/J-05/J-10）、细节缺失类（J-06/J-07/J-09）。其中 J-07（Skill 审核时长）最难——相关内容会被召回但恰不含答案，专测"有相关内容 ≠ 有答案"的边界。
4. **英文 PDF 跨语言题 6 条**（R-01/R-02/R-04~R-07），覆盖 D14–D18、D20 全部可作金标的英文论文；**D19 故意不作金标**，专职做 J-01 的"|Chunk Size|"字面陷阱。所有论文事实均从 PDF 原文抽取核对，不凭印象写。
5. **R-10 计算题是天然的双层归因分离器**：用错单价 → 检索层错；检索对但算错 → 生成层错。D5 归因时优先看这类题。
6. **对照组双向设计**：F-09/F-12/F-13/R-02 等正向题 + M-05"口径一致"题，用于校准 LLM-as-judge 是否无脑给低分/无脑称冲突。

## 四、对 D3–D5 的接口约定

- D3 pipeline 读 `eval_set.json` 的 `question` 字段逐条跑 RAG 问答；
- D4 scoring 按每条 `metrics` 字段选择评分器（规则层/裁判层）；
- D5 归因时用 `gold_doc_id` 判检索命中、用 `trap_note` 对照实际错误路径，输出三层归因标签；
- 拒答题的判分只有一项：`refusal_accuracy`（答了即错，无论内容）。
