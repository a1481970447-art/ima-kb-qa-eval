# D1 痛点笔记：重度使用 ima 的体验崩点（Day 1 同步记录）

> 对应 7 天计划 D1：「同步记痛点笔记：哪一步体验崩了、为什么流失」
> 使用场景：一位 AI 产品经理，把自己的 20 篇真实学习资料（ima 产品资料 + 混元定价 + RAG 论文）导入 ima，当"第二大脑"高频使用
> 记录方法：完整走一遍 导入 → 等待 → 提问 → 核对答案 的旅程，逐环节记录崩点

---

## 一、体验旅程与崩点地图

```
导入语料 ──► 等解析 ──► 提问 ──► 看答案 ──► 想反馈/修正
  ⚠️B-01     ⚠️B-02    ⚠️A-01~24  ⚠️A-14/B-06   🔴 无出口
 (三步链路)  (静默4分钟) (黑盒质量)  (出处难定位)  (反馈闭环缺失)
```

## 二、逐环节痛点（哪一步崩了、为什么流失）

### 崩点 1｜导入：把资料搬进"第二大脑"的成本被低估（⚠️中度流失点）
- **现象**：API 导入一个文件要走三步（申请凭证→传 COS→入库），20 篇文档 60 次调用；客户端手动导入也要逐个拖拽。批量场景（迁移 Notion/飞书资料）没有文件夹级方案。
- **内心戏**："我只是想先把资料放进来，为什么这么费劲？"——重度用户在第一步就流失。
- **产品含义**：导入是知识库产品的漏斗第一级，摩擦直接压低"库变厚"的速度，而库不够厚又导致问答质量差，形成负循环。

### 崩点 2｜等待：解析是黑盒，且会"静默降级"（⚠️高度流失点）
- **现象**：文档入库后约 4 分钟才解析完；期间提问完全可用，但答案里不包含没解析完的文档——**没有任何提示**。我第一轮测了 6 个问题全部 miss，差点得出"检索全崩"的错误结论，核查解析状态后才发现是假 badcase。
- **内心戏**："刚导入就问，答不上来 → 我以为它很笨 → 其实它没读完。"用户不会去查解析状态，只会记住"答非所问"的第一印象。
- **产品含义**：**最危险的一类流失是"沉默的降级"**——功能没有报错，但质量悄悄打了折。正确做法：问答时标注"本回答基于 19/20 篇已解析文档"。

### 崩点 3｜提问：答案质量对用户是纯黑盒（🔴核心流失点，demo 主线）
- **现象 A——错源高排**：问"ima 什么时候上线"，含事实错误的用户帖排第一（"今年 2 月上线"），权威百科排第五。用户无从分辨，因为答案看起来一样自信。
- **现象 B——过期信息无标记**：问"支持哪些平台"，高排的是一年前"仅三种使用方式"的旧帖；问"支持哪些模型"，召回的是旧模型组合。**库越用越厚，旧内容不会自动退休。**
- **现象 C——库外问题不拒答**：问内部参数、竞品数据等库里没有的问题，检索照样返回一堆"长得像"的文档（甚至把错误帖顶到第一），拒答只能赌生成层发挥。
- **现象 D——冲突不可见**：库里两篇文档对同一事实说法冲突（上线时间、价格口径），产品层面零提示，用户每次提问等于抽签。
- **内心戏**："它到底是真的知道，还是在编？"——信任一旦崩塌，用户会退回"我自己翻文档"，第二大脑变成第二硬盘。
- **产品含义**：这不是模型问题，是**知识库质量不可见**的问题——用户需要知道：答案基于哪篇、这篇可信吗、库里有冲突吗。

### 崩点 4｜核对：想验证答案，出处却难定位（⚠️中度流失点）
- **现象**：检索返回的高亮多半是文档摘要或节标题，而不是真正含答案的段落；我的语料里写的内部备注（front-matter 元数据）甚至被当成"答案"高亮出来。英文 PDF 还有乱码高亮。
- **内心戏**："引用了 8 篇文档，但没有一篇告诉我答案在第几段。"溯源成本高 → 用户放弃验证 → 错误答案被默默接受（更可怕）。

### 崩点 5｜反馈：发现答案错了，没有出口（🔴产品机会点）
- **现象**：我发现"上线时间"答案错误、能明确指出该用哪篇文档纠正，但 **没有任何入口** 把这条 badcase 反馈给系统：不能标注"这条答案引用了错误文档"、不能标记某篇文档"过期/有误"、不能对冲突二选一。
- **内心戏**：我最了解我的库，但我帮不了它。
- **产品含义**：用户每一次"发现答案错了"的瞬间，都是最高价值的标注数据——现在全部流失了。这正是提案要做的**反馈闭环**。

## 三、痛点 → 提案功能映射（D7 一页纸的骨架）

| 痛点 | 提案功能 | 优先级 |
|---|---|---|
| 错源高排、冲突不可见（A-01/A-14/B-08） | **知识库健康度面板**：冲突文档对检测 + 信源权威度/时效性标注 | P0 |
| 过期信息无标记（A-05/A-09/A-23） | **过期内容检测**：版本/时间敏感字段识别，问答时降权并提示"引用了 X 个月前的内容" | P0 |
| 解析静默降级（B-02） | **问答透明条**：回答标注"基于 N/M 篇已解析文档"，解析完成通知 | P1 |
| 库外问题不拒答（A-15/16/17） | **拒答信号**：检索置信度低于阈值时前端展示"库内可能没有相关内容" | P1 |
| 反馈无出口（崩点 5） | **badcase 反馈闭环**：答案级"有误"按钮 → 引导用户指认错误源/正确源 → 沉淀为评测集 | P1 |
| 检索范围不可圈定（B-05） | 按文件夹/标签限定问答范围 | P2 |
| 批量导入（B-01） | 文件夹级批量导入 | P2 |

## 四、方法层收获（写给 D3–D5）

1. **评测必须先过"解析状态"关**：任何自动化评测前要轮询 `MEDIA_PARSE_SUCCESS`，否则得到假 badcase（D1 实测踩坑，已写入 pipeline 设计约束）。
2. **MCP 无问答 API** → 端到端问答评测在 ima 侧不可自动化，D3 自建 RAG 复现 + D5 归因是唯一可行路径，且报告须声明"复现架构，结论用于方法论演示"（方案第七节风险对策）。
3. **对照组同样重要**：5 题正常（算力、计费、judge 偏差等），说明问题集中在四类场景——**细节埋深 / 过期错误数据 / 库外问题 / 跨语言 chunk**——D2 金标集按此设计题型，命中率差异才会显著。
4. **给语料写 front-matter 是双刃剑**：内部标注被索引进了检索池（A-14）——D2 做金标时，元数据要与正文物理隔离。

## 五、一句话总结

> "我把自己的 20 篇资料喂给 ima 当第二大脑，第一天就抓到它引用错误帖子回答'产品什么时候上线'。用户永远看不到答案背后的排序和冲突——所以我做的不是又一个 AI 应用，而是让知识库质量**可见、可控、可反馈**的评测工作台。"
